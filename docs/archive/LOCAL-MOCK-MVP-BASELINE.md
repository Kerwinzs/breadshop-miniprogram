# 面包坊小程序：本地 Mock MVP 基线

基线版本：`v0.1.0-local-mock-mvp`

本基线记录当前已经验证的本地 Mock MVP。它用于锁定可演示、可继续重构的业务行为，不代表已经具备生产环境的后端、登录、支付或真实履约能力。

## 已完成流程

- 到店自取：选择门店、浏览商品、加入独立的自取购物车、确认下单、查看订单并推进状态。
- 同城外卖：选择收货地址、加入独立的配送购物车、计算 Mock 保温包装费和配送费、确认下单、查看订单并推进状态。
- 快递邮寄：选择收货地址、切换到快递邮寄、计算 Mock 保温包装费和邮费、确认下单、查看订单并推进状态。
- 地址模块：新增、编辑、删除、选择地址，以及默认地址和地址字段校验。
- 订单模块：订单列表、订单详情、场景和配送方式展示、取消订单、Mock 状态推进，以及已完成订单的“再来一单”。

## 当前 Mock 费用规则

金额在实现中按“分”计算，页面统一按两位小数展示。

| 场景 | 保温包装费 | 配送费 / 邮费 | 订单合计 |
| --- | ---: | ---: | --- |
| 到店自取 | ¥0.00，不单独展示 | ¥0.00，不单独展示 | 商品总额 |
| 同城外卖 | ¥2.00 | 配送费 ¥6.00 | 商品总额 + ¥2.00 + ¥6.00 |
| 快递邮寄 | ¥2.00 | 邮费 ¥12.00 | 商品总额 + ¥2.00 + ¥12.00 |

补充规则：

- 同城外卖和快递邮寄均不设起送价或包邮门槛。
- 配送费或邮费只有在地址完整且支持当前配送方式时才显示具体金额。
- 地址未填写时显示“待填写地址后计算”；地址不完整、超出范围、方式不支持或计费不可用时显示对应阻断提示，不误显示 `¥0.00`。
- 下单前允许切换“同城外卖 / 快递邮寄”，切换后重新校验商品和费用。
- 下单只生成本地“已下单”订单并清空对应场景购物车，不触发支付或资金操作。

## 本地 Storage 数据限制

- 当前状态通过微信本地 Storage 保存，键名为 `breadshopState`。
- Storage 中包含当前场景、配送方式、门店和地址选择、自取购物车、配送购物车及订单数据。
- 数据只存在于当前微信开发者工具或设备的本地环境，不会跨设备、跨用户或跨环境同步。
- 清理开发者工具缓存、清除小程序 Storage、卸载或重装小程序都可能使演示数据丢失；Storage 也不应被视为可靠的订单数据库。
- 当前没有用户身份、权限隔离、并发写入、服务端备份、数据迁移保障或生产级数据校验。
- `MOCK-<时间戳>` 形式的订单号只适合本地演示，不能作为生产订单号方案。

## 后续重构不得破坏的业务规则

- 用户必须在“到店自取”和“外卖/邮寄”之间选择购买场景；配送场景必须区分“同城外卖”和“快递邮寄”。
- 自取购物车和配送购物车必须完全独立；结算或下单一个场景时不得影响另一个场景。
- 配送订单合计必须是商品总额 + 保温包装费 + 配送费/邮费；自取不收取并不展示配送相关费用。
- 地址缺失、地址不完整、超出配送范围、配送方式不支持或费用未计算时，必须给出明确反馈，不能用 `¥0.00` 掩盖未知费用。
- 所有金额必须以分为单位计算并保留两位小数展示。
- 下单不触发支付，只生成“已下单”订单并清空已提交场景的购物车。
- 自取状态流转为：`已下单 → 制作中 → 待自取 → 已完成 / 已取消`。
- 同城外卖状态流转为：`已下单 → 制作中 → 配送中 → 已完成 / 已取消`。
- 快递邮寄状态流转为：`已下单 → 制作中 → 待发货 → 运输中 → 已完成 / 已取消`。
- 只有“已下单”状态允许取消；取消不产生任何资金操作。
- 只有“已完成”订单支持“再来一单”，且必须加入原订单对应场景的购物车。
- Mock 状态推进工具仅用于开发演示，生产构建不得暴露为客户能力。
